# C-006 검토 및 C-007 후속 지시

94,446질문의 전수 상태추적 완료 보고는 채택한다. 27,874채택은 모델 검증 통과이지 의미정확도나 사람 검수 통과가 아니다. qa-02 대규모 SFT 투입은 아직 승인하지 않는다.

## 즉시 마무리
- C-006 9절의 미작성 상태 문구를 실제 EC2 상태·관측시각으로 교체한다. READY 전에 실제 확인을 완료한다.
- 110분 자동종료 원인을 근거와 함께 기록하고 이전 외부 정지 추정과 구분한다. 다른 프로젝트 타이머는 변경하지 않는다. 후속 장시간 작업은 C 전용 새 자원에서 실행할 수 있도록 승인한다. A/B 자원 변경 금지. 시작 전 systemd/cron/인스턴스 종료조건 확인, S3에 실행별 로그 보존 및 재개 설정.

## C-007 범위
1. 같은 질문 키에서 답/판정 충돌이 있는 qa-02 29건 및 qa-01 2건을 추적한다. 첫 행 선택으로 충돌을 숨기지 말고 해당 질문 키 전체를 격리한 조립본을 버전 분리한다. 질문 표현만 같고 근거가 다른 경우와 같은 근거 내 충돌을 구분. 실제 조립 결과의 순서 독립성을 검증한다.
2. qa-02 채택 질문에서 문서분산 고정시드 200건을 AI 의미 검토한다. 모호성/원문외 전제/답 범위/여러 정답/답없음 오표시를 구분한다. 위험추출 표본은 별도로 표시하고 대표 표본 비율과 섞지 않는다. 사람·전문가 검토라고 표시하지 않는다. 단순 문자열일치와 의미정답을 구분한다.
3. C-002 규격을 재사용해 조건·예외·표·다중근거·수치변화·설명 6유형 학습 후보를 각100건, 총600건 목표로 생성·검증한다. 기존 학습용으로 허용된 korea.kr 자료만 사용하고 최종시험 예약문서와 개발평가 문서는 제외. 원문 근거가 없는 유형은 억지로 채우거나 템플릿 복제로 수를 맞추지 말고 부족분을 보고한다. 문서계열 최소200개를 목표로 하고 분할은 문서계열 단위.
4. 먼저 각 유형10건의 실제 생성/검증 경로로 답 범위·근거·출력길이를 확인하고 결함수정 후 확대한다. 이 60건은 개발용 파이프라인 확인이지 성능시험이 아니다. 설명은 실제 설명답을 저장하고 값추출 디코더로 평가하지 않는다. 기존 코드 경로 재사용, 새 평가 인프라 확장 금지.
5. AWS 생성·검증 실행 승인. 데이터 품질 확인 전 새 SFT는 금지하며 A의 동일조건 비교도 변경하지 않는다. 예약 서명 data/benchmark-reserve-001/signatures-partial-148.jsonl로 확보분 본문 겹침을 검사하고 나머지852계열은 unknown 유지.
