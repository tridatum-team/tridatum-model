# C-002 총괄 판정 및 C-003 지시

## 판정: 데이터 형식 파일럿 채택, 설명 능력은 미입증

위험 표본 30개에서 정상17/명확한 결함8/불확실5라는 AI 판정은 전체 데이터 결함률이 아니다. 확인된 의미 오류는 문자열 일치 및 두 모델 동의만으로 정답 품질을 보장할 수 없음을 보여 준다. 확정되지 않은 광범위 필터의 전체 적용은 계속 보류한다.

총괄이 실제 read_rows/encode_example로 30행을 다시 인코딩해 입력·레이블 길이 일치와 설명 5개의 EOS 레이블을 확인했다. 설명 입력 길이는 751~914토큰으로 현재 1024 문맥에 들어간다. pilot-exp-03 정답은 144토큰이어서 128토큰 예약은 일반적인 완성 보장이 아니다.

compat.json의 tokens=2는 실제 길이가 아니다. check에서 encode_example 반환값 `(input_ids, labels)` 튜플의 길이를 기록했다. 기존 인코더는 길이 초과를 예외로 처리하므로 이번 30행의 성공 자체가 무효는 아니지만, 측정값은 고쳐야 한다. 단순 예외 없음이 아닌 정답 전체·EOS 포함 여부를 확인해야 한다.

현재 값 복사 디코더의 설명 정답 수용 0/5는 출력 규격 제약이다. 설명 데이터를 학습하면 자동 해결된다는 증거는 아니다. 새로운 제약 문법이나 템플릿 답변을 만들기 전에 기존 자유 생성 경로에서 실제 모델 출력을 비교한다.

## C-003: 실제 설명 생성 경로와 비교 출력 검증

1. 소유 파일 build_task_pilot.py의 실제 입력/레이블 길이 집계를 수정한다. prompt+고정128 대신 정답 전체와 EOS를 고려한 fit 검증 및 실제 생성 길이 여유를 구분한다. 길이를 넘는 예제를 조용히 자르거나 설명을 값으로 축약하지 않는다. 경계 회귀 검사는 실제 소비자 가시적 초과/보존 동작을 검증하고, 마지막에 관련 검사와 prepare/check를 실행한다.
2. 현재 자체 trid의 가장 좋은 비교 가능한 생성 체크포인트를 명시하고, 기존 자유 생성 경로로 설명 5문항과 나머지 5유형 각1개(고정 id 기준 총10개)를 실제 실행한다. 현재 배포 포인터·기존 값 추출 기본 모드는 변경하지 않는다. 별도 설명 CLI/문법을 불필요하게 새로 만들지 않는다. 필요한 경우 기존 평가 도구에 명시적인 자유 생성 옵션을 연결하되 공용 코드 변경은 A의 학습 경로와 충돌하지 않게 한다.
3. 현재 로컬/S3에 있는 Qwen3-1.7B 및 Kanana-1.5-2.1B 비교용 체크포인트로 같은 10문항을 같은 근거·작업 지시·greedy 조건에서 실행한다. 현재 생성용 C GPU를 빼앗지 말고 별도 승인된 CPU/GPU 자원 또는 유휴 자원을 사용한다. 비교 모델의 base/instruct/LoRA 구분, 해시, 양자화, 프롬프트/템플릿, 생성 한도와 실제 지연을 기록한다. 완료 플래그나 원본 출력이 없는 과거 결과를 재사용한 척하지 않는다.
4. 생성 한도는 설명 gold가 잘리지 않는 범위로 사전 고정한다(예: max_new_tokens=256, 각 모델의 실제 문맥 적합성과 EOS 포함 여부 별도 확인). 모델별 tokenizer가 다르므로 동일 토큰 수가 동일 글자 길이는 아님을 기록한다. 형식 불일치와 의미 오류를 분리한다.
5. 실행 전에 각 문항의 필수 결론/근거/조건을 고정한 체크리스트를 작성한다. 원본 응답을 보존하고 결론 정확, 인용 지지, 조건/예외 누락, 허위 추가 주장, 보류, 잘림을 각각 판정한다. AI 검토라고 명시한다. 이 10개는 이미 작성된 학습/개발 파일럿이며 독립 벤치마크가 아니다. 비교군보다 높은 점수여도 최종 우위를 주장하지 않는다.
6. 실제 생성이 실패하면 실패를 그대로 보고한다. 정답 문자열을 후처리로 덧붙이거나 템플릿/추출 결과를 모델의 설명으로 표시하지 않는다. 결과를 바탕으로 설명 SFT에 필요한 데이터·출력 경로·평가의 다음 변경 하나를 제안한다. 이번 작업에는 새 SFT 학습을 포함하지 않는다.
7. 기존 2만 문서 생성·검증과 내구성 저장·완료 후 정지 절차는 계속 수행하고 별도 상태를 보고한다.
