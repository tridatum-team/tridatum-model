# A-001 총괄 판정 및 A-002 지시

## 판정: 수정 후 진행

역할 분리(raw→clean B, clean→tokens A)와 동일 조건 비교 방향을 채택한다. SageMaker 사용은 승인한다. 기존 C GPU를 기다리거나 변경하지 않는다. 필요한 자원 비용은 사용자 승인 범위다. 기존 B의 실행 역할·S3 규약을 먼저 확인하고 중복 역할이나 자격증명 파일을 만들지 않는다.

아래 실험 해석과 중단 조건은 수정한다.

- 기존 91M은 다른 데이터·초기화·토큰 이력을 가지므로 새 S91-v4와의 차이를 순수 데이터 효과라고 부를 수 없다.
- 390M MHA와 346M GQA+QK-norm은 크기·attention·정규화가 함께 다르다. 비교를 구조의 단일 인과 효과라고 부르지 않는다.
- 큰 모델 검증 손실이 작은 모델보다 낮지 않다는 이유만으로 구현 결함을 확정하거나 중단하지 않는다. 작은 토큰 예산에서 undertraining·최적화 차이가 가능하다.
- 처리량 추정의 50% 미만이면 원인을 점검하되 그것만으로 과학적 실패를 선언하지 않는다. warmup/compile/I/O 이후 지속 처리량을 측정한다.
- 1B에서 하류 개선이 없으면 이번 예산·레시피에서 개선 증거가 없다는 뜻이다. 크기 가설 전체 기각이 아니다.

## A-002: 재현 가능한 크기 비교 실행 준비 및 수치 안정성 파일럿

1. 첫 비교는 신규 91M MHA와 390,128,640-parameter MHA(28층, dim1024, heads16, FFN3072, QK-norm 없음) 두 arm으로 고정한다. 후자는 이름에 실제 크기를 반영한다(예: korean-390m-mha). 346M GQA 후보 설정은 보존하되 첫 비교에 세 번째 arm을 무조건 추가하지 않는다.
2. 데이터는 현재 존재하는 `mix-v3-basetok-tokens`를 동일하게 사용해 B 출력 대기를 피한다. 두 arm 모두 random 초기화, 동일 토크나이저·문맥1024·학습 토큰·출처 샘플링·배치·optimizer·lr 스케줄·seed를 고정한다. 과거 체크포인트는 참고선일 뿐 인과 비교 대조군이 아니다.
3. 먼저 양 arm에 동일 20M 토큰의 실행·수치 안정성 파일럿을 수행한다. 이 점수로 독해 개선을 판정하지 않는다. 실제 step 수/토큰 수, 지속 처리량, 메모리, finite loss/gradient, 체크포인트 저장·재개 동작을 보고한다. 짧은 파일럿이 본 1B 스케줄과 다르면 가중치를 그대로 본 실험에 이어 붙이지 않는다. 이어 쓸 경우 처음부터 1B 스케줄과 optimizer/RNG/sampler 상태를 완전히 보존해야 한다.
4. 필요한 소유 코드/설정 변경을 수행하고 기존 관련 회귀 검사 및 실제 학습 경로 스모크를 최종 변경 후 실행한다. 모델 파라미터 수를 실제 모델로 확인한다. SageMaker 실행 경로는 작업 성공/실패가 제대로 종료되고 원격 체크포인트가 복구 가능한지 확인한다.
5. A-002에서 결과를 보고한 뒤 1B 본 비교는 총괄이 수치 안정성·재현성 증거를 검토하고 지시한다. loss가 finite하다는 사실은 독해력 입증이 아니다. 그동안 B와 clean→tokens 계약 및 파일럿 입력을 정리할 수 있다.
6. B 계약에서 원문/추출본과 학습 적합 clean을 혼동하지 않는다. 평가 오염 해시는 데이터 유출을 막는 비밀 장치가 아니다. 현재 공개 개발 평가에 기존 필터를 재사용하되 비공개 평가 원문·정답을 학습 담당에게 전달하지 않는다. 평가 오염 방지는 train/valid/test 및 출처 간 중복을 함께 고려한다.

## 본 비교 판정 사전 기준

- 주지표는 기존 개발셋 RAG310 답 있음의 엄격 정답(값·출처·형식)이다. 정답 언급 진단치, free 생성, KLUE 질문 민감도, 답 있는데 보류 및 답 없는데 답함을 함께 보고한다.
- 확대 후보: 같은 문항에서 엄격 정답 최소 5%p 개선, 주지표 paired exact McNemar p<0.05, 보류/허위 응답 각각 5문항 초과 악화 없음. 의미 설명 능력 합격으로 해석하지 않는다.
- 이는 개발 후보 선별 기준이며 반복 사용한 개발셋을 최종 독립 성능으로 홍보하지 않는다. 단일 seed 결과의 한계를 명시하고 유망 후보의 재현 확인이 필요하다.
- 같은 SFT mix-04, 동일 SFT token/example exposure 및 decoding 조건을 적용한다. 최종 선택 전 비공개 실제 문서 평가가 별도로 필요하다.
