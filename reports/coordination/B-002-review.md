## B-004: clean-v2 품질 결함 수정 및 실측

- 기존 정제 파이프라인과 PII 함수를 재사용한다. 병렬의 별도 개인정보 처리 규칙 체계를 만들지 말고, 공유 파일 변경 필요 시 소유 세션과 조율한다.
- 실제 잔존 휴대전화/전화번호, 2차 실행 추가 탐지 사례를 재현한 뒤 원인을 수정한다. 같은 고정 10,000행 표본과 raw 재처리 비교로 잔존·오탐·날짜/금액/ISBN 손상을 각각 보고한다. 0건 관측은 전체 안전 보장이 아니다.
- 누락된 유료 보고서 도메인은 기존 격리 경로에 추가한다. 스팸 제거는 확인된 사례에 근거하고 공공문서의 도박 관련 정책 설명 등 정상 문서가 단어만으로 삭제되지 않도록 오탐을 검증한다. 작은 AI 표본을 전체 비율로 주장하지 않는다.
- 개발셋 겹침은 기존 A의 오염 제거 계약과 연결해 제외 증거를 남긴다. 예약 기관 호스트 8,971행은 텍스트 오염 확정이 아닌 잠정 격리. 예약 원문을 일반 학습 데이터에 넣지 않는다.
- 첫 파일에 버전 분리한 clean-v2 파일럿을 실행하고 manifest/hash/실제 표본 결과를 보고한다. AWS CPU 처리 허용. 나머지24파일 확대는 품질 검토 후 결정한다.
- 수집 속도는 호스트 합산 제한, 명시 정책 우선. 정책상 허용되고 제한 응답 없는 경우만 0.5초 간격 소규모 시험, 429/403/지연 악화 시 후퇴. 우회 금지. 대용량 다운로드를 과부하로 오인했던 수정의 실제 재개 결과를 보존한다.
- 기존 인벤토리 effective_date는 시행일이 아니라 revision_date라는 정정을 하위 산출물에 명시한다. 총괄 예약 파일은 불변 유지. 시간 기준 평가에 검증되지 않은 시행일을 사용하지 않는다.
