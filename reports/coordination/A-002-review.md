# A-002 총괄 판정 및 A-003 본 비교 승인

## 판정: 실행 안정성 통과, 1B 토큰 비교 진행 승인

A-002 보고와 실제 파일럿 출력에서 두 크기의 306단계 완료를 확인했다. CUDA fused AdamW 재개 결함 수정, S3 복구 및 CPU 일치 검사 결과를 접수한다. GPU 재개와 비결정성의 오차를 분리하지 못한 한계는 유지한다. 20M 검증손실이나 최대 기울기로 독해 성능·크기 우위를 판정하지 않는다.

총괄이 launch_sm_pretrain.py를 확인했다. 기본 MaxRuntime=7200초는 390M 1B 실행 추정6.2시간보다 짧다. 본 실행은 반드시 명시적으로 충분한 실행 시간을 지정해야 한다. 기본값으로 시작해 강제 종료되기를 기다리지 않는다.

## A-003: 동일 데이터·동일 학습량 본 비교

- 승인: 신규91M MHA와 신규390M MHA 각각 15,259단계·1,000,013,824토큰. 기존 mix-v3-basetok-tokens, tokenizer8192, context1024, seed291101, batch16×accum4, AdamW/lr3e-4/WSD/clip1.0 등 공통 설정을 고정한다. 실제 warmup·감쇠 단계 및 소스 샘플링을 실행 manifest에 명시한다.
- 20M 파일럿은306단계에 맞춘 스케줄로 감쇠했으므로 본1B의 초기 가중치로 이어 쓰지 않는다. 두 arm 모두 새 run/random 초기화로 시작하고 run 경로·S3 prefix를 분리한다.
- SageMaker ml.g6e.xlarge(91M)와 ml.g6e.2xlarge(390M)의 병행 실행을 승인한다. 둘 다 L40S이며 승인된 별도 quota를 사용한다. C GPU나 B 실행 자원을 중단하지 않는다. 가용성 문제면 합리적 대체를 검토하고 차이를 기록한다.
- `--max-runtime 43200`(12시간) 등 여유 있는 deadline을 명시하고 `--stop-after 2000` 체크포인트 세션, MAX_SESSIONS=0(전체진행) 여부를 확인한다. 체크포인트·optimizer·RNG·sampler를 유지한다. 사용자 목표달성 전 AWS 지속 사용 지시를 적용한다.
- 초기 큰 gradient는 clip 전후·finite 여부와 loss를 관찰한다. finite인 일시적 peak만으로 중단하지 않는다. NaN/Inf·반복 실패·체크포인트 손상은 원인 해결 후 동일 조건으로 재개한다. 장애가 나면 결과를 덮어쓰거나 성공으로 표시하지 않는다.
- 현재 데이터에서 예약1000계열의 ID/URL 일치0은 텍스트 누출 부재 증명이 아니다. 본실험은 개발 비교로 진행하며 최종 독립시험 적합성은 B원문 확보 뒤 별도 검증한다. 예약 목록을 데이터 추가에 포함하지 않는다.

## 학습 이후 승인된 작업

1. 두 arm의 동일 1B 최종 step 체크포인트를 사전학습 비교 대상으로 고정한다. 중간 검증 결과를 보고 한쪽만 임의의 유리한 step으로 바꾸지 않는다.
2. 같은 mix-04, SFT1200단계, 동일example exposure·seed·optimizer·lrate·문맥을 적용한다. SFT 체크포인트 선택 규칙도 실행 전에 양쪽 동일하게 기록한다.
3. 기존 RAG310 엄격 정답·정답 언급·free 생성·KLUE 질문 민감도·보류/허위 응답을 개발 진단으로 비교한다. 주 개발 기준은 A-001-review의 엄격 정답5%p 개선/paired p<0.05/위험회귀 제한을 유지한다. 단일seed 및 반복개발셋 한계를 명시한다. 최종 공공업무 우위는 이 결과로 선언하지 않는다.
4. 문맥확장 및 GQA/CPU효율 arm은 결과를 본 뒤 별도 지시한다. 본실험 도중context/구조/새clean mix를 바꾸지 않는다. CPU추론 random가중치1회실측은 참고일 뿐 제품속도보장이 아니다.
