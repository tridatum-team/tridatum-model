# C-005 총괄 판정 및 C-006 지시

## 판정: 수정 채택, 평가 도구 확장 종료

총괄은 동일한 aggregate 재현을 수정된 코드로 실행했다. 정답/오답 판정 순서를 반대로 해도 결과가 동일하고 disagreement=1, full_coverage_correct_rate=null임을 확인했다. AI/human/expert 구분, 부분검수/의견충돌의 미확정 상태를 유지한다. 보고된 테스트 통과는 C의 검증 기록이며 총괄이 전체 테스트를 중복 실행한 것은 아니다.

추가 journal·bootstrap·새 채점 도구 개발은 여기서 종료한다. 향후 실제 최종 평가에서 재현되는 결함만 수정한다. C-003의 작은 개발 스모크 점수는 모델 성능 순위나 도입 합격으로 사용하지 않는다.

## C-006: 기존 2만 문서 QA 생성·검증 작업 완료 인계

- 현재 작업의 생성 완료(32,840문단, 생성 질문94,446)는 보고됐지만 검증은 미완료다. 이미 승인된 검증을 계속 수행한다.
- 완료되면 생성/검증 시도/채택/기각/오류/미처리 수와 상태별 의미를 명확히 기록한다. 채택 수가 적다는 이유로 탈락을 누락으로 오해하지 않도록, 모든 질문이 채택·기각·오류 등 명시적 상태로 추적되는지 확인한다.
- 원문 문서·문단과 초안 ID의 대응, 중복 및 재개 경계 누락, JSON 무결성, S3와 로컬 결과 해시, 사용한 코드/모델/원문 버전을 검증한다. 기존 기각·오류를 성공으로 덮어쓰지 않는다.
- 생성 결과와 실제 학습 투입용 데이터를 구분한다. 이번 데이터는 기본적으로 짧은 값 추출 QA이며 설명/조건 능력이 확보된 것처럼 표시하지 않는다. 알려진 의미 오류 유형과 AI 검증 한계를 기록한다.
- 데이터 조립/provenance를 완료하되 최종 시험 예약 문서가 포함되면 제외한다. 총괄의 benchmark-reserve-001은 ALIO 규정 후보이며 향후 모든 수정본/첨부를 학습에서 제외해야 한다. 이 목록은 정답을 담고 있지 않다.
- 새 학습을 시작하지 않는다. 원격 결과가 내구성 저장소에 보존됐음을 확인한 뒤 타 세션 작업 부재를 점검하고 기존 승인대로 C 인스턴스를 정지한다. NVMe만 남은 산출물이 없도록 확인한다. 실제 정지 결과를 보고한다.
- AWS 과금/자원 권한 승인은 유지된다. 검증 오류나 재개 문제가 있으면 구체적으로 수정하고 재검증하되 완료했다고 위장하지 않는다.

보고: reports/coordination/C-006.md, 마지막 줄 SUPERVISION_REPORT_READY C-006. 완료 전 보고가 필요하면 상태를 진행/차단으로 명시하고 다음 완료 알림 경로도 제시한다. 완료 후에는 추가 기능을 임의로 시작하지 않고 총괄의 학습 데이터 보강 배정을 기다린다.
