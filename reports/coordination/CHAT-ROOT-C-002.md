# CHAT-ROOT-C-002: 일반 대화 개선 후보 실행 결과

작성: C, 2026-11-02. 사용자의 “진단을 바탕으로 개선을 진행하라” 지시에 따라 실행했다. 운영 변경이나 개선 완료 보고가 아니다.

## 1. 실행과 결론

- **실행:** 로컬 MacBook CPU의 기존 원본 GGUF/llama binary에서 새 공개 입력 4개, 총 생성 8회. thinking 비교 4회 뒤 의미 보존 system 후보 비교 4회를 순차 수행했다. 각 조건 seed 17 한 번, 재생성·seed 탐색 없음.
- **미실행:** AWS·운영 mini·배포·학습·수집·기존 공개 20·알려진 실패 문장 재실행. 모델 크기/학습량 원인 주장 없음.
- **결론:** thinking 전환은 채택하지 않는다. 의미 보존 지시는 추가 요청 하나를 없앴지만 원문 사실 누락이 남아 운영 후보로 채택하지 않는다. 생산 코드 변경 0. 효과가 확인되지 않은 문구를 운영에 추가하지 않았다.
- **진전:** “thinking을 켜면 해결”, “의미를 보존하라고 한 문구를 추가하면 해결”이라는 두 개선안을 실제 생성으로 확인했다. 두 방안 모두 이번 관측만으로 해결책으로 승인할 수 없다. 이는 일반적인 무효 증명도 아니다.

## 2. A 진단과 교차 완료

[CHAT-ROOT-A-001](CHAT-ROOT-A-001.md)이 도착하여 읽었다. C001의 A 보고 미도착 항목은 이 보고에서 해소한다.

- A는 A034의 “모델 능력 문제/교체로만 해결”을 철회했다. 현재 생성 구성에서 의미 보존 실패가 관측됐을 뿐 단일 근본 원인은 미확정이라는 C 감사와 일치한다.
- UI는 answer를 출력하고 후처리는 일부 문장 삭제/공백 정리이지 새 확정문이나 질문을 만드는 코드가 아니다. 따라서 공개 운영 사례의 새 술어 생성 위치는 생성 경로로 좁혀진다. 원시 completion과 실제 표시 쌍은 없는 한계가 남는다.
- 현 운영은 non-thinking, sampling, 384토큰/4096 context, 후처리된 history 앞 1500자/24 messages. 부모가 이미 확인한 template parity/role/EOS는 재시험하지 않았다. 이번 `/apply-template`와 `/tokenize` 호출은 생성에 필요한 정상 요청 과정이지 parity 재검증 실험이 아니다.
- A의 최소 확인 요청/확정 진술 대조 제안을 두 번째 실험에 반영했다. 서비스와 direct의 쌍 비교는 이번에 실행하지 않았으며 wrapper가 완전히 무관하다고 주장하지 않는다.

## 3. thinking 비교 — 2개 입력 × 2조건 = 4회

사전 고정 입력:
1. 부품 입고 후 수리 시작, 완료 날짜 미정이라는 고객 안내를 다듬기.
2. 정합적인 고정 history의 검토 요청을 더 짧게 수정: 금요일까지 의견 요청, 무응답을 승인으로 취급하지 않음.

통제: 같은 모델/system/history/seed/sampling, thinking 플래그만 변경. 양쪽 전체 출력 상한 1024, context 4096. 운영의 384토큰과 다른 진단 설정이다. thinking 내부 원문은 저장/보고하지 않고 최종 답만 임시 보관했다.

| 입력 | off | on | 판정 |
|---|---|---|---|
| 수리 안내 | 부품 입고 조건·완료일 미정 보존 | “받아주시면 수리 절차를 시작합니다”로 바뀌어 부품 입고 조건이 사라짐 | off 통과 / on 실패 |
| 검토 요청 후속 축약 | 요청·금요일·무응답 비승인 보존 | 같은 핵심 보존, 이전 고정 답보다 짧아짐 | 양쪽 통과 |

모두 eos, 길이 종료 0. 4회 전부 최종 답이 있었다. 이 두 입력에서는 현재 off가 둘 다 통과했다. on으로 전환할 근거가 없다. 총 생성 토큰은 off 28·29, on 298·273이었다. 단일 seed 결과이며 처리량·정확도 모집단 추정에 쓰지 않는다.

## 4. 의미 보존 system 후보 — 새 최소 대조쌍 × 2조건 = 4회

기존 system에 다음 일반 지시만 더하는 후보 하나를 사전 고정했다. 특정 실패의 정답이나 예시는 넣지 않았다.

> 사용자가 준 글을 다듬거나 번역·요약할 때는 그 글의 뜻과 말하는 사람, 사실·조건, 질문·요청·확정의 구분을 보존하세요. 글 속 질문에 대신 답하거나 원문에 없는 사실·질문을 덧붙이지 말고 요청한 변환을 수행하세요.

입력은 외부 자료 공유에 관한 두 개의 공개 작성 문구다.
- **확인 요청:** 외부 공유 가능 여부를 먼저 검토해 달라, 검토 전 공개하지 말라.
- **확정 진술:** 외부 공유 여부 검토가 끝났고 공유가 승인됐다.

둘 다 같은 정중한 문장 다듬기 작업이다. 원문의 발화 기능·사실 보존과 추가 정보 없음이 사전 기준이다. 모델/seed17/non-thinking/sampling/출력384/context4096/첫 턴 suffix를 고정하고 system만 변경했다.

| 입력 | 기존 system | 후보 system | 판정 |
|---|---|---|---|
| 확인 요청 | 검토 요청·검토 전 공개 금지 보존 | 검토 요청·공개 전 검토 필요 보존 | 양쪽 통과 |
| 확정 진술 | 승인 사실은 남지만 “검토가 끝났다” 누락, “확인해 주세요” 추가 | 추가 확인 요청은 사라짐. 하지만 검토 완료 사실은 여전히 누락 | 양쪽 부분 충족, 후보도 전체 통과 아님 |

모두 eos. 변경한 system이 이 표본의 출력에 영향을 준 것은 관측했다. **잘못된 추가 요청 하나가 사라진 것을 의미 보존 전체 해결로 과장하지 않는다.** 문구나 seed를 바꿔 같은 실패를 계속 재생성하지 않았고, 후보는 생산 코드에 넣지 않았다.

## 5. 판정·구현 한계와 다음 결정

- 판정은 C의 직접 의미 검토다. 팔 이름을 알고 읽었으므로 C001 제안의 블라인드 판정은 충족하지 않았다. 독립 블라인드 평가·통계적 개선으로 보고하지 않는다.
- actual llama `/completion`은 실행했으나 전체 API/UI smoke는 하지 않았다. 채택할 생산 코드 변경이 없어 기존 기관/종료 테스트와 단위 suite도 재실행하지 않았다.
- 현재 결과로 프롬프트 전체를 배제하거나 가중치를 원인으로 확정할 수 없다. 반대로 효과가 불완전한 후보를 “개선됨”으로 배포할 근거도 없다.
- 다음 정보가치 높은 분리는 같은 원본 revision의 reference 실행과 현재 GGUF 실행 간 비교다. 이는 **양자화·변환·runtime 묶음** 비교이지 양자화 단독 인과 증명이 아니다. 자산·로컬 실행 가능성 확인 없이 GPU 기동/다운로드로 확대하지 않는다. 이번 실행에는 포함하지 않았다.
- 직접 생성 실험을 계속 늘리기보다, 부모/A가 판단할 수 있도록 이번 8회 입력 계약·결과·의미 판정을 고정해 넘긴다. 개발량·수집량을 대화 품질 진전으로 대체하지 않는다.

## 6. 실행·자료 안전

- 병렬 ModeProbe/CandidateContract 작업자는 실행 전 공급자 429로 모두 실패했다. 재시도 대기 대신 C가 직접 수행했다. 자식 모델/테스트 실행은 0.
- 로컬 단일 서버를 순차 사용했다. 두 실험 모두 memory pressure 전후 1, 종료 뒤 51992 포트 해제 확인. 유료 자원 기동 0, 운영 접속 0.
- 원시 최종 답과 실행기는 `/private/tmp/chat-root-c-002/`의 평가용 임시 파일이다. 저장소에는 문장 전체를 제외한 메타·판정 `CHAT-ROOT-C-002/evidence.json`과 이 보고만 둔다. 서비스 로그 추가 0.
- 후보용 Git worktree 생성은 timeout으로 등록되지 않았다. 이번 작업에서 생긴 미완료 디렉터리와 임시 서버 로그는 제거했다. 생산 변경이나 정상 브랜치로 취급하지 않았다.
- 최초 mode 4회와 별도 contract 4회를 구분한다. 총 8회이지 “4회만 실행”이라고 보고하지 않는다.
