# C-001 총괄 판정 및 C-002 지시

## 판정: 추가 검증

C-001은 GPU 생성 완료 보고가 아니라 진행 상태·데이터 품질 진단 보고로 접수한다. GPU 빌드/복구 상태는 C가 관찰한 증거이며 총괄이 원격 프로세스를 재측정한 것은 아니다. 총괄은 저장된 train/valid JSONL을 직접 집계하여 총 3,327행과 `확인 불가` 611행을 교차 확인했다.

짧은 정답이 문맥에 존재한다는 검사는 질문의 의미적 정답성과 다문단 조합 후의 모호성을 입증하지 않는다. 20문항 AI 검토에서 결함 2·경계 2가 발견된 만큼 검증 모델 동의만으로 학습 데이터 품질을 합격시키지 않는다. 이 표본을 전수 결함률 추정으로 사용하지도 않는다.

현재 설명·조건·예외 과제가 거의 없다는 진단에 따라 동일 형식의 단순 증량 외에 과제 보강이 필요하다. 기존 승인된 2만 문서 생성·검증은 계속하되 새 학습은 보류한다. 생성 성공을 성능 개선으로 주장하지 않는다.

## C-002: 의미 검증 및 설명 과제 파일럿

1. 기존 GPU 생성·검증 복구와 S3 저장을 계속한다. 완료 시 원본 행 수·무결성·해시·재개 누락/중복 여부를 확인하고, 타 세션 작업 부재 및 내구성 저장을 확인한 뒤 기존 승인된 정지 방침을 따른다. 완료 결과는 C-001을 덮어쓰기보다 별도 후속 보고에 연결한다.
2. 조립된 최종 문맥 기준으로 질문의 지칭 대상, 답의 범위(기간 대 종료일), 복수 가능한 답을 점검한다. 단일 문단 검증 통과가 다문단 정합성을 보장하지 않음을 명시한다. 기존 사례 중 일반형 질문·기간·표를 포함한 위험 기반 30문항을 검토하고, 정상/명확한 결함/판정 불확실을 분리한다. 원문·질문·정답·근거 위치와 판정 이유를 남긴다. AI 검토를 사람 검수라고 표시하지 않는다.
3. 기존 승인된 공공 원문으로 조건, 예외, 표, 두 근거 결합, 수치 변경, 근거 기반 설명 각각 5개씩 총 30개 학습/개발 파일럿을 작성한다. 문서 단위 분할 및 기존 평가 문서 제외를 적용한다. 이 파일럿은 최종 비공개 평가셋이 아니다. 근거가 부족하면 내용을 지어내지 말고 해당 유형의 차단과 필요한 자료를 보고한다.
4. 정답 사실·수치·조건은 원문에서 추적 가능해야 한다. 설명은 원문 인용과 근거 연결을 구분하고, 원문에 없는 정책 사실을 추가하지 않는다. 수치 변경은 원본 문서가 아닌 인위적 변형 예제로 표시하고 원본/변형 provenance와 기대 답을 모두 기록한다.
5. 기존 학습 스키마/조립기를 재사용한다. 새 출력 형식이 기존 값 추출 전용 디코딩·학습 경로와 호환되는지 실제 소규모 prepare/load 실행으로 확인한다. 호환되지 않으면 조용히 값을 추출하는 문제로 바꾸지 말고 필요한 변경 범위를 보고한다. 새 모델 학습은 시작하지 않는다.
6. 현재 코드에서 확정된 소비자 가시적 결함이 있으면 소유 범위 내에서 수정하고 해당 동작을 검증한다. 확정되지 않은 광범위 필터는 대규모 데이터에 바로 적용하지 않는다.
