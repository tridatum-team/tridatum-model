# C-004 총괄 판정 및 C-005 지시

## 판정: preflight/검수 패킷 경로 채택, 다중 검수 집계는 수정 필요

검수 레코드의 AI/human/expert 구분 및 최종 시험 미완료 표시를 유지한다. 1024 출력 한도에서 context1024 모델의 모든 문항이 output_limited인 것은 계산상 당연하므로 그 수 자체를 설명 실패율처럼 해석하지 않는다. 실제 입력·참조 답·생성 EOS/한도 종료를 각각 보고한다. 현재 모델별 지연은 장치·출력 길이가 달라 효율 순위로 쓰지 않는다.

## 총괄이 재현한 결함

`scripts/review_records.py:173`은 같은 reviewer_type의 판정을 `next(...)`로 하나만 고른다. 두 expert가 동일 문항을 각각 정답/오답으로 판정한 입력을 직접 aggregate에 넣고 순서만 바꾸면 correct_rate_over_reviewed가 1.0/0.0으로 바뀐다. 현재 validation은 reviewer_id별 중복만 거부하므로 서로 다른 전문가의 의견 불일치는 정상 입력이며, 이를 첫 판정으로 숨기면 안 된다.

## C-005: 수정 범위 (추가 평가 인프라 확장 금지)

1. 같은 문항·검수자 유형 내 여러 판정을 순서 독립적으로 처리한다. 결론이나 근거/조건/허위 주장 판정이 충돌하면 명시적 disagreement 및 재검수 필요 상태로 남기고 어떤 판정도 조용히 선택하지 않는다. 동일한 독립 판정은 문항 1개로 센다. 보수적인 명시적 합의 규칙을 문서화하고, 현재 합의되지 않은 판정의 공식 점수를 만들지 않는다.
2. 서로 다른 검수자 판정은 원본 그대로 보존한다. AI/human/expert를 서로 합쳐 투표하지 않는다. 동일 문항·동일 검수자의 중복 및 다른 export/run 혼입은 계속 거부한다. 재검수 합의가 별도 근거 없이 있었다고 만들지 않는다.
3. correct_rate_over_reviewed는 부분 검수 진단치라고 명시한다. 전체 대상·실행 실패·검수 완료·미검수·불확실·의견충돌을 함께 보여 주고, 검수가 끝나지 않은 유형의 공식 전체 점수는 미확정으로 둔다. 실패/긴 문맥 문항을 분모에서 숨기지 않는다. 확정 점수/범위의 수학적 의미를 분명히 한다.
4. 총괄 재현을 회귀로 보존한다: 전문가 정답/오답 순서 반전 불변, 동일 합의 문항 1회 집계, 결론은 같고 허위 주장 판정만 다를 때 충돌, AI와 expert 분리, 부분 검수 상태. 마지막에 관련 검사와 기존30응답 export→aggregate 실제 경로를 실행한다.
5. 이번 수정 외 값 형식 journal 추가나 bootstrap 같은 새 기능은 시작하지 않는다. 개발 코드 작업이 최종 평가 문서/골드 준비보다 끝없이 앞서 나가지 않도록 범위를 닫는다.
6. GPU teacher 생성·검증 완료가 도착하면 원본/검증 행 수, 재개 누락/중복, S3 저장 및 hash, 실행 소유권 확인 후 기존 종료 방침을 수행한다. 완료 전이면 진행 상태와 실제 측정 ETA를 적는다.
