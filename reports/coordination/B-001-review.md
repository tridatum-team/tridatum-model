# B-001 총괄 판정 및 B-002 지시

## 판정: 수집 파일럿 채택, 현재 clean v0 학습 투입 불가

B의 보고상 FineWeb 첫 파일 2,783,000문서 변환과 국회 회의록 5건 수집이 완료됐다. 총괄이 원격 23샤드를 전수 재검증한 것은 아니다. 보고된 표본에서 PII 탐지·평가 문서 겹침이 확인됐으므로 clean v0은 학습 적합 데이터가 아닌 정규화된 중간 산출물이다. 파일럿의 처리량·문자 수를 전체 한국어 데이터 토큰 수의 확정값으로 사용하지 않는다.

최종 목표 DOMAIN-GOAL-001에 맞춰 FineWeb은 일반 언어 기반을 보완하고, 실제 기관·업무 문서 및 조건·설명 과제를 별도로 확보한다. 사용자 승인 4종 수집 범위는 모두 유지한다.

## 계약 확정: raw → versioned clean → tokens

B가 `docs/CORPUS_CONTRACT.md`를 작성하고 A/B 제안을 통합한 최종 계약을 소유한다. A의 코드나 파일은 수정하지 않는다.

- raw는 원본 불변, URL/revision/바이트 해시 기록. 기존 v0 샤드와 done 마커를 v1 학습 적합 완료로 재사용하지 않는다.
- clean 경로는 `corpus/clean/<source>/<clean_version>/`, 상태/manifest도 동일 버전을 포함한다. manifest에 원본 revision, 코드/정제 버전, 샤드 키·해시·행 수·분할별 수·필터 사유·작업 ID를 기록한다. 모든 샤드 검증 뒤에 완료 마커를 게시한다.
- 기존 행 스키마에 clean_version, 품질 flags, split을 추가한다. split 값은 train/valid/test로 통일한다. upstream의 분할명은 별도 meta.source_split에 보존한다. upstream test를 개발 valid로 재사용했다면 이를 명시하고 독립 최종 시험이라고 부르지 않는다.
- 기관/업무 유형/문서 날짜/문서 계열·개정 관계가 확인되는 경우 provenance에 보존한다. 모르면 추정값을 확정값처럼 채우지 않는다.
- B는 출처 내부 정제·PII 치환·사용권 근거·중복을 처리한다. A는 출처 간 중복 및 개발 평가 오염 제거·토큰화를 담당한다. 중복 문서가 train/valid/test를 가로지르지 않는지 마지막 경계에서도 검증한다.
- 데이터셋 배포 라이선스와 개별 원문 사용권을 구분한다. ODC-By만으로 모든 원문 이용권이 확보됐다고 기록하지 않는다. 유료 리포트/접근제한/사용권 불명 사례는 학습 후보에서 격리하고 사유를 기록한다. 단순 도메인 차단만으로 전체 사용권 검증이 끝났다고 주장하지 않는다.
- PII 치환은 위험 완화이지 개인정보 부재 보장이 아니다. 정규식 탐지 수와 잔존 위험 표본 검토를 함께 기록하고 원본/중간본은 공개하지 않는다.
- 평가 n-gram 해시는 암호화된 비밀 평가셋이 아니다. 현재 공개 개발 평가의 기존 필터를 재사용하고 비공개 최종 평가 원문·정답은 전달하지 않는다.

## B-002 작업과 승인 범위

1. 소유 수집기를 위 v1 계약에 맞추고 기존 첫 raw 파일을 v1으로 재처리한다. 새 다운로드보다 저장된 원본 재사용을 우선한다. 원본/샤드 재개·완료 마커·해시·분할 정합성을 실제 파일럿에서 검증한다. 확정된 소비자 가시적 오류에만 회귀 테스트를 추가하고 최종 변경 후 관련 검사와 실제 경로 스모크를 수행한다.
2. 샤드 앞부분만이 아니라 고정 seed로 여러 샤드에서 분산 표본을 추출한다. 일반 언어 품질, 숫자·날짜 훼손, PII 잔존, 사용권 격리, 개발 평가 누출을 점검한다. 자동 판정과 AI 표본 검토를 구분한다.
3. 국회 회의록은 진행 중 탐색을 유지하고 상임위·국정감사 본문 표본을 확인한다. 신규 출처의 공공누리/이용 조건은 페이지별 근거와 수집 시각을 남긴다. robots 부재를 이용 허가로 해석하지 않는다.
4. 공공기관·공기업 및 PRISM/정책브리핑/지자체 출처 인벤토리를 착수한다. 기존 자료와 이미 수집된 문서를 재사용하고 기관·업무·시점별 커버리지를 정리한다. 네 출처군을 하나가 끝날 때까지 모두 대기시키지 말고 독립적인 조회/수집 작업은 자원과 요청 제한 안에서 병행한다. 실패한 동일 429 모델을 반복 호출하지 않는다.
5. v1 첫 파일 품질 검토 전 나머지 24개를 학습 적합으로 일괄 승인하지 않는다. v1 보고와 인벤토리를 먼저 제출하면 총괄이 전체 확대를 판정한다. 필요한 CPU·S3 자원은 승인 범위이며 별도 비용 승인을 요구하지 않는다.
6. A가 신규 SageMaker 안정성 파일럿을 준비하므로 기존 실행 역할 이름·실제 허용 S3 prefix·코드/입출력 경로를 계약에 기록한다. 비밀 자격증명은 기록하지 않는다. A의 모델/학습 파일 및 C GPU는 건드리지 않는다.
