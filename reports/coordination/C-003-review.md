# C-003 총괄 판정 및 C-004 지시

## 판정: 실행/재개 기능 채택, 모델 성능 순위 판정 없음

총괄은 세 원본 응답 JSON이 각각 10개 결과를 포함함을 직접 확인했다. C가 보고한 실제 중단·재개 증거는 harness-check.json에 보존되어 있다. 이 개발 스모크를 2,000문항 독립 성능 시험의 대체로 사용하지 않는다.

현재 비교군 설명 대부분이 256토큰에서 잘렸으므로 완성 답변의 설명력 비교가 아니다. 잘림 이후 조건이 없다는 사실과 모델이 그 조건을 모른다는 주장은 다르다. 다만 잘리기 전 생성된 허위 주장은 관찰 가능한 오류다. trid가 설명하지 않아 추가 허위 주장이 없다는 것을 안전성 우위로 해석하지 않는다. CPU와 Metal이 다른 이번 지연시간을 모델 효율 순위로 사용하지 않는다.

공용 평가기의 문맥 한도 상한 처리는 예외를 숨기기 위해 도입되어서는 안 된다. 원래 요청 한도, 실제 사용 한도, 문맥 적합 여부, EOS/잘림을 보존하고 전체 대상 수를 분모에서 유지해야 한다. 긴 입력을 조용히 줄이거나 실패 문항을 빼면 안 된다.

## C-004: 2,000문항 시험에 필요한 비교 조건 및 검수 데이터 경로 완결

1. 현재 개발 자료에 대해 모델별 입력 길이·지원 문맥·예정 생성 한도 preflight를 실행하고, 전체/문맥 부족/길이 제한 위험 수를 분리 보고한다. 실제 2,000문항이 있다고 가정하거나 반복 문항으로 채우지 않는다. 최종 실행 계획은 문서 전체 동일 입력 비교와 공통 문맥 길이 하위 분석을 분리하고, 주지표에서 모델이 처리 못한 문항을 제거하지 않는다.
2. 설명 생성 한도는 기존 256을 고집하지 않는다. 충분한 출력을 위한 모델별 문맥과 tokenizer 비용을 확인해 다음 평가 규격을 사전 확정한다. 개발 출력의 완료율로 한도를 보정할 수 있으나 최종 시험 결과를 보고 유리하게 조정하면 안 된다. 예를 들어 1024 output cap를 쓸 수 있는 비교군은 그 조건을 명시하고, trid는 지원 문맥의 한계를 정직하게 기록한다. 별도 동일예산 비교는 보조 분석으로 구분한다. 이번에는 같은 10개를 반복 실행해 정확도 숫자를 늘리는 작업을 하지 않는다.
3. 기존 출력과 checklist를 받아 검수 가능한 레코드를 생성/검증하는 경로를 기존 평가 코드와 호환되게 완성한다. 필드에는 item ID, 문서 계열, model/run/prompt/checklist 해시, 원본 응답, 생성 종료 상태, 결론/근거/조건/허위 주장, 검수자 유형(AI/human/expert), 판정 근거, 미검수/불확실 상태가 있어야 한다. 모델명을 가린 검수 패킷과 원본 매핑을 구분하고 기존 AI 판정을 human으로 변환하지 않는다.
4. 의미 정답을 문자열 포함이나 문법 검사만으로 자동 확정하지 않는다. 객관적으로 검사 가능한 출처·단위·숫자 검사는 보조 증거로 두고, 미검수/불확실 의미 판정은 점수 0이나 정답으로 임의 대체하지 않는다. 채점 완료율과 모델 실행 실패/잘림은 별도 분모로 공개하며 최종 완결 판정에서 미검수 항목을 숨기지 않는다.
5. 실제 기존 30개 모델 응답과 checklist를 사용해 내보내기→판정 기록→집계의 전체 경로를 실행한다. 모든 응답이 정확히 한 번 대응하고, 누락/중복/다른 run의 판정 혼입/AI-human 오표시를 탐지하는지 검증한다. 아직 없는 전문가 판정은 명시적으로 미검수다. 필요한 회귀 검사는 최종 변경 뒤 한 번 실행하고 결과를 보고한다.
6. 최종 2,000문항 문서·정답 작성에는 접근하지 않는다. B가 준비하는 문서 커버리지와 총괄의 독립 제작/검수 절차에 연결할 입력 계약만 명시한다. 이 작업 완료를 최종 벤치마크 완료라고 표시하지 않는다.
7. 진행 중 teacher 생성·검증은 계속한다. 완료 시 행 수/무결성/중복/누락/S3 해시와 저장을 검증하고 기존 정지 방침을 따른다. 아직 미완료라면 별도 상태로 보고한다.
