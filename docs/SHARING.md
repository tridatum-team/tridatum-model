## 일반 대화와 근거 검색 (TRID-CONVERSATION-001, 기본 버전)

- **경로 선택:** 서비스 모델 자신이 2단어 문법(`검색` | `대화`)으로 처리 경로를 고른다. 키워드 규칙이나 고정 응답은 없다(GENERAL-CHAT-001).
  - 2-word grammar는 입력 하나만 분류한다. 직전 턴이 일반 대화였으면 직전 사용자 입력을 함께 적어 준다. 그래야 "그 중에 하나만 골라줘", "두 문장으로 줄여줘"가 검색으로 가지 않는다.
  - 직전 턴이 근거 검색이었으면 직전 입력을 적지 않는다. 대신, 기관·문서명이 없는 입력 중 직전 문서가 전체 최고 점수의 60% 이상으로 답하는 것은 이어지는 검색으로 본다(`Workspace.continues`).
  - 정의·통계 표지(뜻·차이·평균·집행 등)는 모델이 검색으로 고른 입력에만 적용한다.
  - 검색으로 갔지만 자료에 맞는 근거가 없을 때, 다음 조건을 모두 만족하면 일반 대화로 답하고 `scope`에 그렇게 적는다:
    - 직전 턴이 검색이 아니다.
    - 기관·규정명이나 업무 기준 단어(`RULE_CLAIM`)가 없다.
  - 위 조건에 해당하지 않는 업무 질문은 계속 "근거 없음"으로 답한다.
- **일반 대화:**
  - 모델의 기본 chat template에 이 세션의 저장된 대화(최근 24개 메시지)를 들어가는 만큼 모두 넣는다. 들어가지 않으면 오래된 턴부터 뺀다.
    - GENERAL-CHAT-002 진단: 이전의 고정 6개 창은 프롬프트가 4,096토큰 중 479토큰뿐인데도 5턴째에 사용자의 첫 말("견과류 알레르기")을 잘랐다.
  - 근거 검색 턴은 넣지 않는다. 앞선 대화를 묻는 질문에만 넣는다.
  - 시스템 지시는 역할과 말투만 정한다. 규정 안내 문구를 넣으면 1.7B 모델이 일상 질문까지 "기관 규정을 확인하세요"로 돌렸기 때문이다.
  - 생성 설정은 Qwen3 비사고 권장 샘플링(temperature 0.7, top_p 0.8, top_k 20, presence_penalty 1.5)이다. 분류와 문서 답변은 그대로 greedy다.
  - 버전별 대화 계약을 검증할 때는 관리자 `versions.json`의 해당 버전에 `chat_system`(문자열), `chat_sampling`(생성 설정 객체)을 지정할 수 있다. 일반 대화와 검색 실패 후 일반 대화 전환 경로가 모두 그 버전의 값을 쓴다. 설정이 없으면 위 기존 계약을 그대로 쓴다.
    - `chat_sampling`은 기존 설정에 일부 키를 합치는 방식이 아니라 해당 객체를 전달한다. temperature/top_p/top_k/min_p/penalty 등 검증한 값을 명시해야 한다.
    - 첫 턴 안내, history 범위, 숫자 주장 후처리는 그대로다. 일반 설명의 `EXPLAIN_SYSTEM`과 검색·분류 프롬프트도 바꾸지 않는다.
    - 선택 설정 `chat_thinking: true`는 `/v1/chat/completions`와 `enable_thinking`을 사용한다. 파싱된 최종 `message.content`만 사용자에게 전달하고 history에 넣으며, `reasoning_content`는 사용하지 않는다. 최종 답이 없으면 내부 추론으로 대신하지 않고 오류로 처리한다. 생각 모드가 켜져 있어도 모델이 매번 내부 추론을 생성하는 것은 아니다.
    - `chat_max_tokens`는 일반 대화의 출력 토큰 예산이며 미지정 시 기존 384다. native 모드에서는 내부 추론과 최종 답이 이 예산을 함께 사용한다. `finish_reason: length`는 기존 출력 잘림 안내로 연결한다.
    - `chat_reasoning_budget`를 지정하면 해당 llama-server에 `--reasoning-budget`를 전달한다. 같은 모델·context라도 이 예산이 다르면 서버를 공유하지 않으므로 다른 port를 지정해야 한다. 모델/template 및 고정 llama.cpp 버전의 지원 여부를 먼저 확인한다.
    - 프로세스 메모리 설정 `no_repack: true`, `batch_size`, `ubatch_size`, `cache_ram`을 지정하면 각각 `--no-repack`, `--batch-size`, `--ubatch-size`, `--cache-ram`을 전달한다. 생략한 플래그는 추가하지 않아 기존 실행 기본값을 유지한다. 이 설정은 일반 대화뿐 아니라 같은 서버의 검색·분류에도 적용된다.
    - 이 메모리 설정이 다르면 같은 모델·context라도 서버를 공유하지 않으므로 다른 port가 필요하다. 같은 설정은 기존처럼 공유한다. 실제 `State`에서 앞의 세 설정의 공유/분리, 622-token 입력의 생성, 자식 종료를 로컬 CPU로 확인했다. 모델 가중치 파일은 바꾸지 않으며, 개발기 검증은 운영 16GB 맥미니의 메모리 여유나 후보의 문안 품질을 보장하지 않는다.
    - `cache_ram`은 [고정 llama.cpp의 RAM prompt cache 상한](https://github.com/ggml-org/llama.cpp/blob/8ca4060/tools/server/README.md)을 MiB로 지정하며 `0`은 해당 캐시를 끈다. 모델 가중치나 실행에 필요한 KV/상태 메모리를 없애는 옵션은 아니다. 지원하는 런타임에서만 지정하고 전체 메모리 압력은 별도로 확인한다.
    - `cache_ram`도 실제 `State`에서 미지정/0, 0/32의 두 시나리오로 공유·분리를 확인했다. 생략 시 플래그가 없고 0/32가 실제 시작 인자에 전달되었으며, 각 서버에서 계산을 생성한 뒤 자식과 포트를 회수했다. 시작 전·적재 후·종료 후 압력은 1이었다. 이는 실행 경로 검증이며 모델의 불필요한 첫 대화 안내까지 품질 통과로 승인한 것은 아니다.
    - 위 선택 설정을 생략하면 기존 비사고 `/completion` 경로와 예산을 유지한다. C005 로컬 CPU 실 UI에서 native 설정, 최종 답 표시와 후속 대화 연결, 종료를 확인했지만 문안 품질의 잔여 오류가 있어 운영 승인을 뜻하지 않는다.
    - native 경로의 종료 토큰 처리도 모델별로 확인해야 한다. 기존 Kanana Q8에서는 EOS 메타데이터가 정상인데도 `peg-native` 응답 본문에 `<|eot_id|>`가 노출됐다. 같은 가중치의 실제 비사고 `chat_reply` → `/completion` 경로는 EOS를 정상 처리했다. 따라서 native 설정을 다른 모델에 자동 적용하지 않으며, 제어 문자열을 사후 삭제해 품질 통과로 처리하지 않는다.
    - 전역 `CHAT_SYSTEM`/`CHAT_SAMPLING`을 수정하지 않으므로 다른 버전의 대화 계약을 덮어쓰지 않는다. HTTP 요청에서 이 설정을 받지 않는다.
    - 이는 검증된 계약을 연결하는 기능이지 후보의 운영 합격이나 기본 모델 교체가 아니다. 이번 변경은 배포 versions 파일을 수정하지 않는다.
  - 출력 문자 제한과 반복 재생성은 하지 않는다. 고유명사·번역(일본어·중국어·Café 등)이 그대로 나오고, 모델이 가끔 중국어를 섞거나 직전 답을 되풀이하는 것도 그대로 보인다(모델 한계).
  - 근거 검색을 하지 않으며 "일반 대화 · 검증 대상 아님"으로 표시한다.
  - 숫자를 숨기는 문장(API 응답에도 남기지 않음, 숨긴 개수를 알림): 숫자+단위가 업무 기준 단어(규정·수당·여비·식비·연가·공무원·기관 등)와 같은 문장에 있는 경우다. 사용자가 준 숫자는 숨기지 않는다.
  - 일상적인 숫자는 숨기지 않는다. 예: 커피 2잔, 20분 산책, 11월 3일부터 휴가.
  - 앞선 대화를 묻는 질문("아까 내가 어디 간다고 했지?")은 이 세션의 기록을 넣어 모델이 자연스럽게 답한다.
  - 기록이 없으면 모델 없이 "아직 나눈 이야기가 없다"고 답한다. 새 대화의 첫 턴에는 앞선 내용이 없다는 것도 모델에 알린다.

  - **기관명 인식** (RETRIEVAL-REGRESSION-002):
    - 기관명은 두 자료로 인식한다.
      - B agency-aliases-v1: 공식 근거가 있는 별칭.
      - 「정부조직 약칭과 영어 명칭에 관한 규칙」 [별표]의 중앙행정기관 공식 약칭: `data/official-abbreviations`, 현행 행정안전부예규 제390호.

    - 약칭으로 인식한 경우 어느 판 기준인지 `scope`와 `abbreviations`에 적는다.

    - 이렇게 바꾼 경우 `scope`에 적는다.
    - 법령에는 적용하지 않는다.
    - 사례를 묻는 질문은 지침의 사례 구간을 그대로 쓴다.
  - **기관을 되묻는 목록:** 각 기관의 본문과 함께, 그 문서의 별표가 검색을 통과했으면 별표도 함께 보인다. 단, 질문에 없는 조건의 별표(아래 "조건이 다른 별표", 예: "출장비"에 공무원 여비 규정 [별표 8] 상시 출장)는 되묻기 목록과 다른 문서 목록(`others`) 어디에도 넣지 않는다(MODEL-RESUME-A-024·025, 후보 브랜치 `model-resume-024`, 배포 전).
    - 기관을 말하지 않은 질문에서 특정 기관의 자체 규정(제목이 기관명으로 시작하거나 B `applies_to`가 institution)은 공통 규정의 경쟁 후보가 되지 않는다. 다만 적용 범위 기록이 없는 규정은 공통 규정으로 보지 않으므로, 자체 규정도 경쟁 후보로 남아 되묻는다. 예: "국외출장 계획서 작성 방법" → 방위사업청 관리규정 단독 답 대신 기관 되묻기(MODEL-RESUME-A-024).
  - **앞선 대화 질문:** 위 일반 대화 경로로 답한다. 검색 답변은 세션 기록에 근거 문서와 확인된 인용만 남아 있다.
  - **공공기관 전반을 묻는 질문:** 한 기관 자료로 답하게 되면, 답 맨 앞에 그 기관 한 곳의 자료이며 대표값이 아니라고 적는다. 해당하는 경우는 그 기관의 별도 색인, 정형 값, 자체 규정을 쓴 답이다.
    - 같은 질문에서 되묻기 후보가 모두 특정 기관의 자체 규정이거나 공무원에게만 적용되는 규정이면(B `applies_to`, 별표는 그 규정의 기록), 목록 앞에 "공공기관 공통 기준을 찾지 못했고 후보는 공공기관 전체 기준이 아님"을 적는다. 적용 범위 기록이 없는 후보가 하나라도 있으면 붙이지 않는다(RETRIEVAL-CONTINUE-007, 코드만 반영, 배포 전).
    - 공공기관 범주 질문("공무원"을 말하지 않음)에 고른 규정이 공무원에게만 적용되는 규정(B `applies_to` central/local_government)이면, 단일 답 대신 같은 안내와 후보 목록으로 되묻는다(`reason: population`). "공공기관 출장비"와 "그러면 공공기관의 출장비"가 같은 처리를 받는다(MODEL-RESUME-A-025, C-025 4.2, 배포 전).
  - **`context_limits`:** 응답의 `context_limits`에는 모델 문맥 한도 때문에 실제로 뺀 개수가 들어간다. UI는 0이 아닌 항목만 답변 아래 한 줄로 보인다(UI-SCOPE-004).
  - **서식·용어·적용 범위 (RETRIEVAL-ROOT-008, 코드만 반영, 배포 전):**

      - term-map의 `not_equivalent` 행(6행, 보류 중인 REB 행동강령 인용)은 읽지 않는다. 로더가 이 행을 읽게 바뀌면 C 재판정이 필요하다.

  - **조건이 다른 별표 (RETRIEVAL-ROOT-009, MODEL-RESUME-A-024·025, 후보 브랜치, 배포 전):**
    - 별표의 조건은 캡션에서 규정명·표 종류(…표)·그 규정 별표 절반 이상에 공통인 낱말(여비, 지급)을 뺀 것 가운데, 그 별표를 인용한 본문 문장의 절(「별표 N」 앞부분)이 수식어로 말하는 것만이다. 절의 주제(마지막 은/는 앞 명사, 예: "국외 항공운임은", "위험근무수당은")는 표가 정하는 대상이라 조건이 아니다. "X이 아닌 사람"은 "X 아닌" 한 단위다. 예(공무원 여비 규정): 별표 2 국내, 별표 4 국외, 별표 6의2 국외·가족, 별표 8 상시·출장, 별표 9 "공무원 아닌", 별표 1·3·5 조건 없음. 본문이 인용하지 않는 별표는 조건이 없다. 고정 단어나 별표 번호로 판단하지 않는다.
    - 질문이 조건 단위를 모두 말하거나 그 별표를 직접 이름으로 부르면("별표 2 식비") 그 별표를 쓴다. 아니면 그 별표는 근거가 아니다: 본문 안에 들어 있는 별표 구간, 본문 인용으로 연결하는 별표 문서, B 검토 표 행 모두 넣지 않는다. 예: "공무원 여비 규정에서는 숙박비가…"(국내·국외 미지정)는 별표 2·4 값 없이 본문으로 답하고 "경우에 따라 다른 표를 쓴다: 별표 2(국내 …), 별표 4(국외 …) … 해당하는 경우를 넣어 다시 물어봐 달라"를 답 맨 앞에 적는다(`tables_set_aside`). 국내를 말하면 별표 2, 국외를 말하면 별표 4만 쓴다(C-025 4.1, P1–P3).
    - 가장 가깝게 검색된 문서가 이런 별표이고 규정 본문도 검색을 통과했으면 본문으로 답하고 `table_condition`과 `scope`에 적는다(예: "출장비 지급 기준" → 본문, [별표 8] 상시 출장 아님). 남은 근거가 모두 그런 별표 구간이면 모델을 실행하지 않고 경우를 되묻는다(`reason: table_condition`).
    - 이어지는 질문(같은 문서를 잇는 후속)은 직전 답이 말했거나 이어받은 경우를 이어받는다. 예: "…국내 출장 식비는?" 다음의 "그럼 숙박비는?"은 별표 2(국내)를 쓰고, `scope`에 "앞 질문에서 말한 조건(국내)을 적용"이라고 적으며, 응답 필드는 `conditions_carried`다. 다음 경우에는 이어받지 않는다(MODEL-RESUME-A-030, 후속 브랜치 `model-resume-030-followup`, 배포 전).
      - 그 질문이 이 규정의 다른 경우를 말할 때. 지금 말한 쪽이 우선한다. 예: "그럼 국외는?"
      - 기관·규정을 명시해 전환할 때
      - 문서를 고정(pin)했을 때
      - 새 대화를 시작할 때. 기록이 지워진다.
      - 표 하나의 조건 낱말 중 일부만 말했을 때는 그 경우를 말한 것으로 보지 않는다. 예: "출장"만으로는 별표 8(상시·출장)이 아니다.
    - 한계: 같은 표를 다른 말로 부르면(예: "해외" ↔ 국외, "위험수당" ↔ 위험근무수당) 조건을 말하지 않은 것으로 본다.

## 사용

- 기관·규정명을 넣어 물으면 업무 질문은 공유 검색 색인에서 근거를 찾습니다. 다른 후보 문서는 `/doc 번호`로 고정할 수 있습니다(고급 기능).
- `/pdf`, `/paste`로 넣은 문서가 있으면 그 문서에서만 찾습니다. 텍스트 PDF는 2MB·20페이지·5만 자, 붙여넣기는 5,000자까지입니다.
- 모델 파일은 방문자에게 내려주지 않습니다. GGUF와 llama.cpp 실행 파일은 `runs/`에 있으며 기동할 때 sha256을 검사합니다.

PDF와 질문은 Cloudflare HTTPS 중계를 거쳐 운영자의 맥미니로 전송됩니다. 비공개·민감한 자료 대신 공개 가능한 테스트 자료만 사용하세요. 앱은 문서와 질문을 파일·학습 자료로 저장하지 않습니다. 문서는 HttpOnly/Secure/SameSite 세션별 메모리에 저장되며, 지우기 또는 15분 미사용 후 정리됩니다. Cloudflare 자체 네트워크 처리·메타데이터 정책과는 별개입니다.

2026-10-27 연결 복구: 터널 프로세스가 살아 있어도 실제 연결이 0개인 상태가 발생했습니다. 이제 시작 시 터널의 `/ready`와 외부 HTTPS 모델 응답을 모두 확인하며, 실행 중에는 30초마다 검사합니다. 두 번 연속 실패하면 모델 서버를 유지한 채 터널을 재시작하고 Worker의 연결 주소를 재배포합니다. 새 터널의 DNS 음성 캐시를 피하기 위해 외부 상태 검사는 요청별 DNS-over-HTTPS를 사용하며 Mac의 DNS 설정은 변경하지 않습니다. 복구 중 잠시 중단될 수 있고, 네트워크·Cloudflare 인증 문제가 지속되면 자동 복구도 완료되지 않을 수 있습니다. `status`의 `connection_status`, `last_health_at`, `recoveries`로 확인할 수 있습니다.

  - 문장으로 바꿔 말한 출력은 답으로 표시하지 않음도 확인했다.
  - **배포 경로 동작 검증이지 정확도 측정이 아니다.**

새 DNS 레코드는 일부 네트워크의 이전 NXDOMAIN 캐시 때문에 약 30분 늦게 보일 수 있습니다. 권한 DNS, Cloudflare 1.1.1.1, Google 8.8.8.8에는 새 주소가 반영됐습니다. 접속이 안 되면 잠시 후 또는 다른 네트워크에서 다시 시도하세요.
